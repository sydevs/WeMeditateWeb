# AGENTS.md

This file gives AI coding agents guidance for this repository.

> `CLAUDE.md` is a symlink to this file for Claude Code compatibility. The nested guides under
> `server/`, `components/` and `pages/` use the same symlink pattern. Claude-specific features
> (hooks, skills, settings) stay in the `.claude/` folder.

This guide stays short on purpose. It states only facts that apply everywhere and that the code
does not show directly. Rules for one part of the tree, or steps for a procedure, load on demand
from a rule or a skill. See [Where everything lives](#where-everything-lives).

## Debugging: confirm with evidence before concluding

Pages here render on the server from live PayloadCMS data. Source code alone often does not show
the real behavior. Before you form or act on a root-cause hypothesis, do this:

- **Fetch the real output.** Use `curl` on the deployed preview. Confirm the actual HTML (`<h1>`,
  nav `href` values, error markers) instead of guessing what renders.
- **Query SahajCloud directly.** Call the REST API to see which fields populate. Confirm whether a
  relationship returns a populated object or a bare id before you blame the query or the code.
- **Read the request, not only the response.** The dev server logs
  `[PayloadCMS] GET <url> → <status>`. Use this log to confirm the exact query string and status
  code the SDK sent.
- **When local access is blocked, confirm in CI instead.** A local **403** usually means the
  `.env.local` key is stale. The atlas endpoints are the exception: they 403 locally even with a
  valid key, because the local client lacks the `sahaj-atlas-client` role. `GET /api/clients/me`
  tells the two apart. See [local-environment](docs/local-environment.md). Then confirm against
  the deployed preview through CI.
- **Run an experiment to settle competing hypotheses.** When two hypotheses seem possible (for
  example, "the query is wrong" vs "the data is unpublished"), test query variants against the
  real API. Do not argue from the code alone.

In past sessions, confident hypotheses were often wrong until confirmed against real data. Prefer a
quick experiment over reasoning from source code alone.

## Cloudflare Workers Deployment

The Worker holds no bindings and no persistent state.

A second, assets-only Worker is configured here for the Ladle playground
(`design.wemeditate.com`), in [wrangler.design.jsonc](wrangler.design.jsonc) — a filename
wrangler does not auto-discover, so `pnpm deploy` keeps resolving `wrangler.toml`.
`pnpm check:wrangler` is what reads the design config in CI. That Worker serves every PR preview,
and `design.wemeditate.com` as a Workers Custom Domain (sydevs/SahajAtlasWeb#266). See
[docs/cloudflare-previews-ci.md](docs/cloudflare-previews-ci.md).

Content reads are cached by the **Cloudflare edge in front of SahajCloud** for 600s, which a
`Cache-Tag` purge on write may shorten but never guarantees. Nothing in this repo caches them. See
[server/CACHING.md](server/CACHING.md) before you add a read.

Keep browser-only libraries out of the Worker bundle: [components/AGENTS.md](components/AGENTS.md).

## Repo-wide conventions

These rules apply whether or not the matching rule file or skill is loaded.

- **A route-owned path needs a `[slug]` exclusion.** See [pages/AGENTS.md](pages/AGENTS.md).
- **Translations are SahajCloud-owned. Never write a user-visible literal.** Every string the site
  renders — visible copy and every `aria-label` or `sr-only` label alike — comes from the
  `wm-web-translations` global, through `useT()`. `lib/translations.en.json` is the committed
  English mirror, generated by `pnpm sync:translations`; it is the fixture for tests and Ladle
  and the fallback when the SahajCloud read fails, never a place to add a string by hand. A new
  string is added to the SahajCloud schema upstream first (`sydevs/SahajCloud`), then reaches this
  repo through `pnpm types:cms` and `pnpm sync:translations`. A site that cannot be fixed yet
  carries an `eslint-disable no-restricted-syntax` region whose reason names the blocker — never
  a bare one. A tree that is not visitor copy at all goes in the `no-restricted-syntax` block's
  `ignores` in [eslint.config.js](eslint.config.js) instead, beside the stories, Ladle and the
  Sentry trigger page.
  A language's own name, a brand name, and a list separator are not translations: use
  `Intl.DisplayNames`, the platform's own label, and `Intl.ListFormat`.
- **A string composed in English is still an English string.** `` `Mute ${label.toLowerCase()}` ``
  and `` `Loading ${title.toLowerCase()}` `` build a sentence only English builds that way. Take
  the finished label as a prop or a key, never assemble one from a visible label.
- **An indexable content route builds its head in `+data.ts`, and that is its whole opt-in.** The
  `+data.ts` builds one `SeoDocument` through [lib/content-seo.ts](lib/content-seo.ts) — the
  title, the canonical, the `hreflang` cluster, Open Graph, Twitter and a `@graph` described as
  plain data ([lib/seo-schema.ts](lib/seo-schema.ts)) — and
  [lib/seo-head-html.ts](lib/seo-head-html.ts) generates the head string from it with Unhead, on
  the server, once per request. A route that builds none publishes no URL claim at all, which is
  what keeps the `embed` routes and the error page bare. **The generator is declared once**, as
  `headHtmlEnd: seoHeadHtml` in `pages/+config.ts`: vike-react's setting is global as well as
  cumulative, so a second declaration on one route adds a second copy of the whole head to every
  page of the site. `<title>` and `description` sit beside it, from
  [lib/head-settings.ts](lib/head-settings.ts), which has to be a separate module and says why.
  **Never a head hook in a component**: `PageTemplate`, `MeditationTemplate` and
  `LectureTemplate` are shared with the `embed` routes and the live preview, and none of those is
  a URL to point a crawler at. `/map` is the one route still rendering its head as a component —
  `SeoHeadTags` in [lib/head.tsx](lib/head.tsx), over the pre-serialized answer SahajCloud sends
  ([lib/atlas-head.tsx](lib/atlas-head.tsx)).
  A URL advertises only the locales its own document is published in —
  [lib/hreflang.ts](lib/hreflang.ts) owns that derivation for the page head, the
  `og:locale:alternate` list and `/sitemap.xml`, so the three cannot disagree. The site's
  `availableLocales` is a filter on that set, never the set itself.
  `tests/guards/content-head.test.tsx` holds both halves: the head is declared in one file, and
  the routes that build a document are the ones listed there.
- **Nothing site-wide goes in `public/`, so a site-wide document is a route.** `/robots.txt`,
  `/sitemap.xml` and `/manifest.webmanifest` are all Hono routes
  ([server/sitemap-routes.ts](server/sitemap-routes.ts)) for that reason, and being routes is also
  what lets the manifest answer in the language of the URL. The platform's own identifiers — the
  store ids, the theme colour, the home-screen icon — live in
  [lib/app-identity.ts](lib/app-identity.ts), which is not
  [lib/site-identity.ts](lib/site-identity.ts): that one is who the site is on the web, the
  profiles the footer links and `Organization` claims.
- **One geometry for the embedded player.** [lib/embed-player.ts](lib/embed-player.ts) owns the
  iframe and its size, because three surfaces name the same player: the paste-ready snippet
  (`EmbedButton`), the `twitter:player` and `og:video` tags, and `GET /oembed`
  ([server/oembed/](server/oembed/)). A width that differed between them would letterbox the
  player in one consumer and crop it in another. Which URL the iframe points at is
  `documentEmbedHref`'s, in [lib/document-routes.ts](lib/document-routes.ts).
- **How a URL is spelled lives in [lib/urls.ts](lib/urls.ts), not in a consumer.** `Link`,
  `EmbedButton`, the language dropdown, the canonical and the `hreflang` cluster all read the same
  answer from there. Never restate one of these rules at a call site. **An absolute URL for one of
  our own pages is `absoluteHref`**, not an origin glued onto `localeHref`: the embed snippet and
  a content-index card's `ItemList` entry both need one, and it leaves an off-site URL alone.
  A **scheme** is part of that spelling: `isSafeHttpUrl`, `isSafeNavigationUrl` and
  `isSafeLinkHref` live there too, and any URL
  the site did not author itself passes one of them before it reaches an `href` or
  `window.location` — they are what stops a configured `javascript:` value running in our origin.
  Which one is the destination's: `window.location` takes the first two, and an `href` takes
  `isSafeLinkHref`, the only one that admits what an editor legitimately types — a site path, a
  bare `#anchor`, `mailto:` and `tel:`. **The `Link` atom applies that one itself**, so an href
  reaching an anchor through `Link`, or through an atom that delegates to it, is already gated and
  the call site adds nothing. `tests/guards/bare-anchors.test.ts` is what keeps that true: no
  component may open an `<a>` outside the atom, and its allowlist is the whole exception list.

  **One exception, and it is about what renders, not about safety.** A call site gates a value it
  also passes to `Link` when a refused URL must render **nothing** — `Splash`'s call to action,
  `AtlasContent`'s website link and `ErrorFallback`'s status page all do, because the atom renders
  the words inert and words inviting a click that goes nowhere are worse than an absent element.
  `isSafeHttpUrl` is the gate where the URL must additionally be absolute: a status page in
  `target="_blank"` (`ErrorFallback`), and anything the atlas publishes, whose canonical
  `sitePathFromUrl` parses.

  An **absolute URL on our own origin** is ours to spell, and `isSitePath` rejects it, so
  `localeHref` passes it through untouched. `sitePathFromUrl` is that case: it hands back the path
  under such a URL in `normalizeContentPath`'s spelling, ready for the caller to locale-prefix,
  and `null` for every other URL and for an unknown origin. Upstream canonicals arrive this way.
  `atlasHref` is its only caller, and `Link` passes such a URL through untouched by design (#124).
- **`/index` is routing-internal, never a URL.** A redirect target, a canonical and an `hreflang`
  href all go through `normalizeContentPath`, and a request spelling `/index` itself 301s to its
  locale's home page.
- **Two hooks write `pageContext.locale`, and only these two.** `pages/+onBeforeRoute.ts` sets it
  wherever routing runs. A thrown `render(<status>)` renders the error page from the pre-routing
  pageContext, so routing never happens there — `pages/+onCreatePageContext.server.ts` covers
  that one path, and only when `locale` is still absent. Never guard a consumer against an
  undefined locale; the type says `Locale` and those two make it true.
- **UI must be mobile-first and meet WCAG 2.1 AA.** See
  [design-system](docs/rules/design-system.md) for the full rules, including breakpoints and
  touch-target sizes.
- **Test a batch edit on one file before running it everywhere.** Pipe the substitution through
  `diff` against a single file first. Run `perl -i` on the full set only after you confirm the
  `diff` output.
- **Never stop a Chrome debugging process (port 9222), or any process you did not start.** Other
  Claude instances may share this Chrome debugging session.
- **Mapbox is the preferred mapping provider for this project.**
- **The backend is called SahajCloud, not "the CMS".** Files, symbols and prose spell it
  `SahajCloud` / `sahajCloud`. `PayloadCMS` and `@payloadcms/sdk` name the product instead, and the
  `[PayloadCMS] <method> <url> → <status>` log prefix stays as it is. Three modules keep a name
  that is neither: `lib/payload-relationships.ts` describes the product's field shapes,
  `lib/content-blocks.ts` the upstream editor's block shapes, and `lib/document-routes.ts` paths
  on **our own** site — `documentHref` resolves one, so it is not `sahajCloudHref`.
- **`@payloadcms/live-preview-react` is pinned exact, and the version it is pinned to is
  SahajCloud's own `payload` version, not the newest published one.** It is the one dependency
  whose semantics are the producer's rather than a standard's: it merges a `postMessage`
  SahajCloud mints, and `lib/live-preview/document.tsx` hands it the whole transport. A caret
  would let a fresh resolve carry it ahead of the CMS (#222 did; #248 restored the pin). Move it
  when SahajCloud moves, in the same bump as `@payloadcms/live-preview`,
  `@payloadcms/richtext-lexical` and `@payloadcms/sdk`. `live-preview-react@<v>` depends on
  exactly `live-preview@<v>`, so both take one version or `pnpm-lock.yaml` carries two copies.
  SahajAtlasWeb's `docs/rules/data-layer.md` states the same rule for the other consumer.
- **`public/` is shipped by both builds, so nothing site-wide goes in it.** The Vike app's build
  and the Ladle build each copy it, so a `robots.txt`, `_headers` or `_redirects` there applies to
  the app and the playground alike. The playground's crawler refusal lives in `.ladle/static/`
  for that reason — see [docs/cloudflare-previews-ci.md](docs/cloudflare-previews-ci.md).

## PR Workflow (3 Phases)

PRs move through three phases. The point is to batch CI runs. Do not push on every small change,
because each push re-triggers the `gate` and `smoke` jobs and both Cloudflare preview builds.

1. **Implement.** `/implement-ticket <n>` takes a ticket through this sequence: plan, branch,
   implement and test, then the lean local gate. It then hands off to `/finalize-pr`, which opens
   the PR as a draft and pushes. Neither skill waits for CI.
2. **Adjust.** While you work on an **open PR** — follow-up tweaks after `/implement-ticket`, or
   any later change on the PR branch — commit each change locally as you go. Do not push during
   this phase. Batching avoids a CI re-run on every small tweak.

   This phase overrides the usual "commit and push only when asked" default. During Adjust,
   commit follow-up changes locally without being asked, and never push them yourself. The user
   can still say "hold off" to pause the automatic committing.
3. **Finalize.** `/finalize-pr` ships the batch.

   Run `/finalize-pr` when the PR is ready for review or merge.

Skills come from the **`workflow` plugin** (`sydevs/claude-workflow`). Each skill exists in exactly
one place, so no parity spec needs syncing across repos.

**Commit and PR conventions**: Use Conventional Commits. Find the scopes in current use in
`git log --oneline -50`. Do not invent a new scope.

## Where everything lives

Path-scoped and procedural guidance does not live in this file. It loads on demand, from four
places.

**Path-scoped rules** (`.claude/rules/`) apply to one part of the tree. Claude Code injects a
rule when it reads a matching file. A rule with no `paths:` loads in every session. The prose
text lives in `docs/rules/`. `.claude/rules/` holds only symlinks to those files, and Claude Code
cites the `docs/rules/` target.

This indirection is deliberate. Claude Code's Protected Paths guard requires interactive approval
for any write under `.claude/`, ahead of `permissions.allow`. A rule body stored there would
stall an unattended run that tries to update it. The same file under `docs/` stays freely
editable. **Do not move a rule body back into `.claude/`.**

| --- | --- | --- |
| [code-comments](docs/rules/code-comments.md) | every session (no `paths:`) | When a comment earns its place, and the comments never to delete. Synced from `claude-workflow`: edit the canonical block there |
| [design-system](docs/rules/design-system.md) | `components/**`, `layouts/**`, `pages/**` | Atomic-design classification, mobile-first requirements, Icon/Button/Link/Divider patterns, refactoring to variants |

**Nested guides** are an `AGENTS.md` file with a `CLAUDE.md` symlink beside it. Its folder
location defines its scope, so it needs no frontmatter. Codex and Cursor read it, as well as
Claude Code.

- [server/AGENTS.md](server/AGENTS.md) covers `server/**`. PayloadCMS reads must send `select`
  (plus `populate` at depth > 1) and `locale`. Filter out unpublished relationships that return a
  bare id, and log a Sentry warning instead of rendering a dead link.
- [components/AGENTS.md](components/AGENTS.md) covers `components/**`: browser-only libraries.
- [pages/AGENTS.md](pages/AGENTS.md) covers `pages/**`: the `[slug]` matcher's exclusions.

skill relevant.
